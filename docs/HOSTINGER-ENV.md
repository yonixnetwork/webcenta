# Webcenta — Hostinger environment variables (checklist)

Where to enter them: **hPanel → Websites → webcenta.com → Node.js → Environment variables**.
After adding or changing any variable, **redeploy** (hPanel → Node.js → Deployments → Redeploy, or push to
`main`): the build copies the variables into the app, so a plain restart is not enough.

Every name below is read by the application (the complete, machine-checked list is
[CONFIGURATION.md](CONFIGURATION.md)). Values are left blank for you to fill. Never put real values in GitHub.

Many integrations can **also** be configured later in **Admin → Settings** (stored encrypted in MySQL, applied
within seconds, no redeploy). A value saved in the dashboard always wins over the environment variable of the same
purpose. Integrations marked *dashboard only* have no environment variable at all.

## 2. First-time setup (needed now, once)

The production database is still empty and no owner account exists. From this release the tables and base data are
created **automatically** on the first start after deployment; you only need the token to create the owner account.

| KEY | VALUE | SOURCE | REQUIRED |
| --- | --- | --- | --- |
| `SETUP_TOKEN` | `openssl rand -hex 32` | Generated by you; you type it into `https://admin.webcenta.com/setup` | Yes, until the owner account exists |

After the owner account is created, `/setup` is **permanently locked** (a lock record in the database), even if the
token is still set. Then delete `SETUP_TOKEN`.

## 5. Google OAuth (Google sign-in) — free

1. https://console.cloud.google.com/apis/credentials → **Create credentials → OAuth client ID → Web application**
   (configure the OAuth consent screen first if asked).
2. **Authorised redirect URIs:** `https://webcenta.com/api/auth/callback/google` and
   `https://developers.webcenta.com/api/auth/callback/google`.
3. Copy the Client ID and Client secret.

| KEY | VALUE | SOURCE | REQUIRED |
| --- | --- | --- | --- |
| `GOOGLE_CLIENT_ID` | | Google Cloud Console → Credentials | For Google sign-in |
| `GOOGLE_CLIENT_SECRET` | | Same OAuth client | For Google sign-in |

## 6. Apple OAuth (Sign in with Apple) — Apple Developer Program, US$99/year

1. https://developer.apple.com/account/resources/identifiers/list/serviceId → create a **Services ID**
   (e.g. `com.webcenta.signin`), enable Sign in with Apple, add the domains `webcenta.com` and
   `developers.webcenta.com`, and the return URLs `https://webcenta.com/api/auth/callback/apple` and
   `https://developers.webcenta.com/api/auth/callback/apple`.
2. https://developer.apple.com/account/resources/authkeys/list → create a key with **Sign in with Apple**,
   download the `.p8` file (only downloadable once) and note its **Key ID**.
3. Your **Team ID** is shown at the top right of https://developer.apple.com/account/.

| KEY | VALUE | SOURCE | REQUIRED |
| --- | --- | --- | --- |
| `APPLE_CLIENT_ID` | | The Services ID identifier | For Apple sign-in |
| `APPLE_TEAM_ID` | | Apple Developer account (10 characters) | For Apple sign-in |
| `APPLE_KEY_ID` | | The Sign in with Apple key (10 characters) | For Apple sign-in |
| `APPLE_PRIVATE_KEY` | | Contents of `AuthKey_XXXXXXXXXX.p8`, on **one line** with `\n` where the line breaks are | For Apple sign-in |
| `APPLE_APP_BUNDLE_IDENTIFIER` | | Only if a native iOS app signs in | No |
| `APPLE_CLIENT_SECRET` | | Legacy alternative to the key (a pre-generated JWT, expires ≤ 6 months) — leave empty when using the key | No |

Webcenta signs Apple's client secret from your key itself and renews it automatically.

## 7. GitHub OAuth (GitHub sign-in) — free

1. https://github.com/settings/developers → **OAuth Apps → New OAuth App**.
   Homepage `https://webcenta.com`, callback `https://webcenta.com/api/auth/callback/github`.
2. Generate a client secret and copy both values.

| KEY | VALUE | SOURCE | REQUIRED |
| --- | --- | --- | --- |
| `GITHUB_CLIENT_ID` | | GitHub OAuth App | For GitHub sign-in |
| `GITHUB_CLIENT_SECRET` | | GitHub OAuth App | For GitHub sign-in |

A GitHub OAuth App allows one callback URL, so this enables GitHub on the marketplace. To offer it on the developer
portal too, create a second OAuth App with callback `https://developers.webcenta.com/api/auth/callback/github` and
enter it in **Admin → Settings → GitHub OAuth** (dashboard only).

## Steps

1. hPanel → Node.js → Environment variables: add `SMTP_PASSWORD`, `SETUP_TOKEN`, and any provider keys you have
   (sections 5–7, 10); delete `ADMIN_AUTH_SECRET`. Keep every other existing value. Save.
2. Redeploy (Deployments → Redeploy, or merge to `main`). The runtime log then shows
   `[webcenta] auto-migrate: Applied 1 migration(s)…` on the first start.
3. Open `https://admin.webcenta.com/setup`, enter `SETUP_TOKEN`, create the owner invitation, open the link, set a
   password and enrol your authenticator app. `/setup` is now locked for good.
4. Delete `SETUP_TOKEN` from hPanel and redeploy.
5. Admin → Settings: run **Test connection** for Email, Google, Apple and GitHub; enable each provider once its test
   passes. Do one real sign-in with each provider.
